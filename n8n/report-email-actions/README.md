## 변경 내용 (워크플로우마다 동일)
1. NocoDB 조회 노드의 `fields`에 `ai_summary,ai_flags` 추가
2. `HTML 리포트 생성` → **`이메일 액션 삽입`**(Code, `inject-email-actions.js`) → `Gmail — 리포트 발송`
   - `__DASHBOARD_URL__`: 대시보드 주소, `__SOURCE_NODE__`: 해당 워크플로우의 NocoDB 조회 노드 이름
   - 텔레그램 노드는 그대로 `HTML 리포트 생성`에 연결
3. 각 물건 행 아래에 AI 요약(180자) + `⭐ 관심 추가` + `📄 AI요약·명세서 보기` 버튼 추가
   - 버튼은 대시보드 `functions/api/item.js` (`/api/item?id=…`)로 연결
   - `&action=interest` 링크는 클릭 한 번으로 `is_interested=true, interest_level=1, interested_at` 저장 (대시보드 toggleStar와 동일)
   - 낙찰/유찰 물건은 상세 보기 버튼만 표시

기존 `HTML 리포트 생성` 코드는 수정하지 않으므로, 되돌릴 때는 새 노드만 빼고 Gmail을 다시 연결하면 됩니다.

## 링크 서명 (2026-11-12, API 보호)
대시보드 `/api/*`가 로그인을 요구하게 되면서, 메일 버튼 링크에는 물건별 서명 `&sig=`가 붙습니다.
- `inject-email-actions.js`의 `__DASHBOARD_SECRET__`을 Cloudflare Pages 환경변수 `DASHBOARD_SECRET`과 **같은 값**으로 넣습니다.
- 서명 링크는 그 물건 하나의 보기와 관심 등록만 허용합니다. 다른 API는 로그인 세션이 필요합니다.
- `⭐ 관심 추가` 링크는 이제 GET으로 바로 등록하지 않고 확인 버튼을 한 번 더 누르게 합니다(메일 스캐너 자동 클릭 대비).

## 행 매칭 방식 변경 (2026-11-17, AI 요약 중복 수정)
예전에는 `사건: {사건번호}`로 행을 찾았습니다. 그래서 한 사건에 물건이 여러 개면(예: 2025타경12046의 4·5·6·7층) 형제 물건들의 AI 요약이 모든 행에 중복으로 들어갔습니다.
- 이제 두 워크플로우의 `HTML 리포트 생성` 노드가 행마다 `<!--item:{Id}-->` 표식을 남기고, `이메일 액션 삽입`은 이 표식으로 자기 행 하나만 찾습니다.
- 같은 수정에서 층 표시 `7층층` → `7층`으로 고쳤습니다(`floorText`).
- `HTML 리포트 생성`을 되돌리면 표식이 없어져 AI 요약이 아예 안 붙습니다. 두 노드는 함께 되돌리세요.
